# Horizontal Timeline Axis (`el-horizontal-timeline-axis`)

[← Back to root README](../../../README.md)

---

## What it does

The shared, rendered-once time axis — grid tick marks, hour labels, the time-of-day gradient bar, and the horizontal-zoom +/− control — that sits above all six [HorizontalTimeline](../horizontalTimeline/README.md) rows at the `≥1024px` desktop breakpoint, so this chrome isn't repeated per row. One instance is mounted by [HorizontalTimelineStack](../horizontalTimelineStack/README.md).

## Files in this folder

| File                        | Role                                                                                                                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `horizontalTimelineAxis.js` | The custom element: grid/hour-label generation, the future-overlay, and the zoom buttons.                                                                                                                                                                                 |
| `zoomConstants.js`          | `NATIVE_ZOOM`/`MAX_ZOOM`/`ZOOM_STEP` and `getEffectivePxPerMinute(zoomLevel)` — imported cross-folder by [HorizontalTimeline](../horizontalTimeline/README.md) too, since both need the same zoom math. Lives here since zoom conceptually belongs to the axis's control. |

## Custom element

`<el-horizontal-timeline-axis>` — no attributes or props; one instance per stack.

## Store interaction

- Reads `currentDate` to drive the live future-overlay (see below).
- Reads/writes `horizontalZoomLevel` (Phase 10.5): the +/− buttons dispatch `SET_HORIZONTAL_ZOOM` with the current value ± `ZOOM_STEP` (see [`zoomConstants.js`](./zoomConstants.js)), clamped to `[computeMinZoom(), MAX_ZOOM]`. Doesn't read or write any Entry data.

## Behaviour notes

- **Grid/hour labels (Phase 10.5) are generated by `renderGrid()`**, not static markup — a tick every 10 minutes (mirroring the vertical [Timeline](../timeline/README.md)'s own `#grid-lines` resolution), solid-gray on the hour, dashed on the half-hour, plain otherwise; hour labels via `formatOffsetAsClockTime()` (`src/utils/time.js`), so they correctly reflect whatever `day_boundary` the config sets rather than assuming `04:00`. Regenerated on every zoom change, along with the `<svg>`'s own `width`/`viewBox` and the gradient bar's `width` — all recomputed from `getEffectivePxPerMinute(zoomLevel)`, keeping 1 viewBox unit = 1 CSS px at every zoom level. Grid colors were ported verbatim from the original design handoff's `timeline-horizontal.svg` (deliberately left unchanged — functional data-viz encoding, not decorative chrome).
- **Zoom range:** `NATIVE_ZOOM` (1×) up to `MAX_ZOOM` (4×) in `ZOOM_STEP` (0.25×) increments. The minimum is computed dynamically, not fixed — `computeMinZoom()` reads the current `clientWidth` of this element's parent (`HorizontalTimelineStack`, the `overflow-x: auto` scroll container) so "zoomed all the way out" always shows the whole day with no horizontal scrollbar at the current viewport width, matching the handoff note's intent. Not reactively re-clamped on a later window resize.
- The future-overlay (greys out now→end-of-day), axis-swapped (`x`/`width` instead of `y`/`height`) from `Timeline.updateFutureOverlay()`, also scales with the current zoom level — refreshed on a `setInterval` (cleaned up via `registerCleanup`) and re-checked on a date or zoom change, hidden entirely when the viewed Diary date isn't the actual current day.
- Uses its own `horizontalTimeGradient` gradient id, distinct from the vertical template's `timeGradient`, since both templates' clones can be live in the document at once (one per breakpoint).
- The zoom buttons are `position: sticky; right: 0` within the scrolling stack, so they stay reachable regardless of horizontal scroll position — styled off `DESIGN.md`'s `button-icon-circular` token (44×44px, translucent chip background, full radius).

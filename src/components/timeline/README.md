# Timeline (`el-timeline`)

[← Back to root README](../../../README.md)

---

## What it does

Renders one Dimension's Timeline for the currently-viewed Diary day as an SVG time axis, with a block per recorded Entry. It's the main interactive surface of the diary: pressing and dragging across empty space paints a new Entry (a plain click makes a 30-minute one), clicking an existing block opens it for editing, and long-pressing (or holding the mouse down on) an Entry reveals drag handles for resizing its start/end time in place. One instance is mounted per Dimension by [TimelineStack](../timelineStack/README.md).

Terminology (Dimension, Timeline, Entry, Primary activity mirror) follows [CONTEXT.md](../../../CONTEXT.md).

## Store interaction

- Reads/writes this Dimension's Entry array for the current Diary date (`state.diaries[currentDate].timelines[dimensionIndex]`), dispatching `ADD_TIMELINE` (first mount), `ADD_ENTRY`, `UPDATE_ENTRY`, and `DELETE_ENTRY`. Saving a brand-new Entry (not an edit) also immediately reveals its resize handles, as if it had just been long-pressed — see `BaseTimeline.saveEntry()`.
- Dispatches `SHOW_PANEL`/`HIDE_PANEL` to open/close [DetailsPanel](../detailsPanel/README.md).
- Non-Primary-activity Timelines additionally read the Primary activity Dimension's own Entries to render the read-only "mirror" strip alongside their own — see `renderShadowDimension()` (internal name "shadow"; the domain-facing term is "Primary activity mirror" — see [CONTEXT.md](../../../CONTEXT.md)).

## Interaction pipeline (`entryResizeController.js`)

`EntryResizeController` is constructed by `BaseTimeline.createResizeController()` with a small set of injected dependencies (the SVG element, the entries/handles layers, and callbacks for reading entries, checking single- vs multiple-choice Mode, checking whether the details panel is open, coordinate conversion, and committing a resize back to the store) rather than reaching into `Timeline` directly. Since Phase 10.6, it's also used by [HorizontalTimeline](../horizontalTimeline/README.md), generalized via an injected `axis` config (`Y_AXIS`/`X_AXIS`, exported from this file — which SVG attributes carry "position along the timeline" vs "fixed cross-axis center": `y`/`height`/`cy` for vertical, `x`/`width`/`cx` for horizontal) and an injected `getPxPerMinute()` callback rather than a hardcoded constant (each subclass's `getPxPerMinute()`: `Timeline`'s is just `PX_PER_MINUTE`; `HorizontalTimeline`'s reads the current zoom level on every call, since only the horizontal view zooms). Everything else in the controller already operated purely in minutes, not pixels, so needed no changes at all for this. It owns:

- Long-press detection (hold ~500ms without moving far → reveal resize handles).
- Drag tracking and live visual feedback as a handle is dragged.
- **Moving an Entry by its body** ([move-resize flow](../../../docs/design/flows/move-resize.md)): a drag whose `edge` is `'body'`. A mouse press on an Entry that moves more than ~10px starts it straight away (a press held still still reveals the handles, as before); on touch, a long-press arms it, and moving the same finger then picks the Entry up (`moveArmed`), so scrolling is never taken away. The pointer's travel from the slot it picked the Entry up at, in 10-minute slots, is the move; `computeMove()` (`moveSpan.js`) turns that into the Entry's new span and the spans of the neighbours it is trimming, which are redrawn live with the handles, and the new times are one readout at the start edge. Release commits the Entry and the trimmed neighbours in one `store.batch`; a move that ends where it began stores nothing. Escape or `pointercancel` puts everything back; after Escape the still-down pointer is ignored (`ignoredPointerId`) and its click swallowed. The click that ends any move is swallowed too, so the Entry does not also open. A move never starts while the details panel is open.
- **The neighbour gives way** ([move-resize flow](../../../docs/design/flows/move-resize.md)): on a single-choice Dimension, dragging an edge that touches another Entry (it ends where this one starts, or starts where this one ends) moves that neighbour's facing boundary too, so there is never a gap or an overlap. It lengthens when the edge is dragged away from it and shortens when dragged into it, but is never shrunk below 10 minutes and never deleted: the drag stops there instead. `findAdjacent()` picks the neighbour when the drag starts; `adjacentSpan()` says where its boundary is for the drag as it stands, and the neighbour's block is redrawn live. An edge with a gap beside it moves only itself, and stops at the next Entry beyond the gap. Multiple-choice Dimensions tolerate overlapping Entries, so nothing else moves.
- Clamping a drag to: the 10-minute minimum duration, the neighbour's own minimum (above), the Diary day's own bounds, and — only when editing the actual current Diary day — "now". When a drag is held against a limit, the handle's readout says "limit" as well as the block flashing.
- Committing a completed drag (via a callback into the host, `BaseTimeline.onCommitResize`) as a single `UPDATE_ENTRY` dispatch, or, when a neighbour moved too, as one `UPDATE_ENTRY` per Entry in a single `store.batch` (`EntryCommands.updateMany`), so subscribers see one change and never the two Entries half-updated. A cancelled drag (Escape, `pointercancel`) puts both blocks back with no dispatch at all.

`BaseTimeline` keeps thin delegating methods (`onEntryPointerDown`, `onEntryPointerMove`, `commitDrag`, `cancelDrag`, `onGlobalKeyDown`, plus `activeDrag`/`activeHandleEntryId` getters) so this remains the single entry point external callers — and the test suite — use.

## Behaviour notes

- **Creating an Entry** ([create-entry flow](../../../docs/design/flows/create-entry.md)): `EntryCreateController` handles a press on `gridline-zone` and a drag across it, snapped to 10-minute slots. The span comes from the pure `clampCreateSpan()` in `createSpan.js`: clamped to the free space around the pressed slot on a single-choice Dimension (a multiple-choice one may overlap), the day edges, and "now" on the current day. While the pointer is down, `CreatePreview` draws a dashed block with its start–end times as text (saying "limit" when something cut it short). On release the panel opens through `panelActions.openNewEntry(start, end)`, and the block stays until the panel closes, the Dimension or date changes, or an existing Entry is opened (`BaseTimeline.syncCreatePreview()`). Escape or `pointercancel` creates nothing. A press that never leaves its slot is a plain click, which `BaseTimeline.onTimelineClick` turns into a `DEFAULT_NEW_ENTRY_MINS` (30) block, as much of it as fits; with no room at all it flashes "No room here" and opens nothing. On touch, the finger must rest ~150 ms before painting starts; moving first reads as a scroll and is left alone. The click that ends a drag is swallowed, so a drag never also makes a plain-click block.
- Click-to-create/click-to-open coordinate math goes through `BaseTimeline.clientToSvgCoord()` (`getScreenCTM()`/`SVGPoint.matrixTransform()`), not `event.offsetY` — `offsetY` assumes 1 CSS pixel equals 1 SVG viewBox unit, which breaks whenever the SVG renders narrower than its viewBox (e.g. under certain zoom/accessibility text-scaling conditions), silently shrinking the whole coordinate system including the time axis. This was a real Chrome-only bug found on a physical Android device; see `timeline.test.js`'s regression test for the exact scenario.
- Touch-drag scroll interference (the resize handles fighting the scrollable [TimelineStack](../timelineStack/README.md)) is defended against twice: `touch-action: none` (CSS + a class toggled for the drag's duration) as the primary defense, and a non-passive `touchstart`/`touchmove` `preventDefault()` as a belt-and-braces fallback for browsers whose `touch-action` support on freshly-inserted SVG shape elements is a frame stale.
- Entry blocks are rendered as an SVG `<rect>` plus a `<foreignObject>` containing an HTML `<div>` label (not SVG `<text>`), so long labels can wrap across multiple lines via ordinary CSS.
